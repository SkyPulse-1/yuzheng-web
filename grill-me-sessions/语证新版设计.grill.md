# Grill Session: 语证新版设计

Started: 2026-09-01
Last updated: 2026-09-01
Status: complete
Domain: 语证 Web App 的产品设计、信息架构与交互体验；本轮不执行代码修改

## Summary

将现有临时“粘贴文字分析”升级为正式、可跨设备同步的知识库资料，遵循“先保存、后分析、产出四部分结论”的流程；分析内容必须能够回到来源原文核验。证据问答改为问题卡片库和全屏详情，全站采用现代学术档案馆视觉语言与克制的玻璃动态，并在不修改学校 HiAgent 后台、不清空现有数据的前提下完成。实施前后均执行密钥与代码安全扫描，按阶段提交 Git，只先交付本地版本。

## Decision Log

### RESOLVED: 方案名称
- **Resolution**: 本次方案记录名称为“语证新版设计”。
- **Date**: 2026-09-01

### DECIDED: 粘贴文字的正式保存与分析流程
- **Decision**: 粘贴内容先作为当前知识库内的一份正式“文字资料”保存，允许设置或修改标题；保存成功后再由用户启动分析。原文和四部分分析结果均持久保存，同一账号刷新页面或更换设备后仍可查看。
- **Rationale**: 让粘贴文字与上传文件遵循一致、可理解的“先保存资料，再分析内容”流程，并满足跨设备同步和历史回看需求。
- **Date**: 2026-09-01

### DECIDED: 四部分结论结构
- **Decision**: 每次正式分析固定产出“内容摘要、关键观点、原文依据、信息不足与歧义”四个部分。界面始终显示四张主卡；某部分没有可靠内容时显示“暂未发现”，不得补写或编造。HiAgent 返回内容需要按固定结构接收，不能依赖对自由文本标题的猜测拆分。
- **Rationale**: 固定结构让用户能快速比较不同资料的分析结果，也能避免模型输出格式变化造成卡片缺失、错位或误导。
- **Date**: 2026-09-01

### DECIDED: 结论卡片的主交互
- **Decision**: 卡片默认显示简短预览，悬停时轻微放大并强化轮廓；点击卡片后放大为全屏详情。在全屏详情中，鼠标悬停于“分析总结中的内容”时，以小窗口显示它所依据的来源原文上下文；上下文距离核心证据句越远，文字视觉上越淡。手机改为点击总结内容打开上下文，键盘选中后按回车打开，再次点击或点击空白处关闭。
- **Rationale**: 首页保持紧凑、便于扫描，用户需要深读时再进入沉浸式详情；上下文浮窗帮助判断引用是否被断章取义。
- **Date**: 2026-09-01

### DECIDED: 总结与来源的可追溯规则
- **Decision**: “内容摘要、关键观点、原文依据”中的每条内容必须绑定至少一处可靠来源原文，才能作为可核验结论显示并提供上下文查看。“信息不足与歧义”允许在没有直接原文时显示，但必须标记为“综合判断”。找不到可靠来源的普通结论不显示，也不生成虚假引用。
- **Rationale**: 保证用户可以从总结回到原文核验，同时承认“缺失或歧义”本身未必对应单一原句。
- **Date**: 2026-09-01

### DECIDED: 证据问答主布局
- **Decision**: 取消右侧独立证据卡栏。页面中上方改为问题卡片列表，下方保留固定输入框；提交后立即生成“分析中”卡片，完成后显示问题、回答摘要、证据数量和时间。点击问题卡片进入全屏详情，查看完整回答、证据卡和来源上下文。文档范围选择保留，但收纳为顶部简洁筛选栏。
- **Rationale**: 消除现有中间区域的大块空白，让问答结果形成可浏览、可回看的任务卡片，并把回答与其证据集中在同一个详情中。
- **Date**: 2026-09-01

### DECIDED: 问题卡片历史管理
- **Decision**: 问题卡片永久保存并支持同一账号跨设备查看；按最新提问优先排序，首次加载最近 12 张并支持继续加载；支持按问题文字搜索；允许用户删除，但删除前必须二次确认。
- **Rationale**: 将证据问答从一次性会话升级为可检索的研究记录，同时控制首屏信息量和误删风险。
- **Date**: 2026-09-01

### DECIDED: 全站视觉方向
- **Decision**: 采用“现代学术档案馆”方向：米白纸张底色、深墨色文字、深靛蓝品牌主色、暖金色证据强调，结合编号、引用标记、克制的纸张层次和清晰网格。首页、知识库、文档和证据问答使用有区分度的布局，但共享同一设计语言。加入轻量的类玻璃动态，只在导航、交互卡片和全屏详情使用轻微透明、折射感、跟随光泽与柔和放大，不采用明显或大面积的强玻璃效果；支持减少动效设置。
- **Rationale**: 强化“语证”的学术、核验和档案主题，同时保留高级感、可读性和性能，不让动效抢夺内容注意力。
- **Date**: 2026-09-01

### DECIDED: 已分析文字资料不可修改
- **Decision**: 粘贴文字在开始分析前可以检查和修改；一旦启动分析，资料标题和正文均锁定为只读。需要修改时，用户必须先删除知识库中的原资料，再创建一份新的文字资料并重新分析，不保留“编辑后沿用旧结论”的路径。
- **Rationale**: 论文、课本和研究材料通常不需要持续编辑；锁定内容能确保原文、四部分结论和来源上下文始终对应，避免版本混淆。
- **Date**: 2026-09-01

### DECIDED: 资料回收站保留 30 天
- **Decision**: 删除资料时先将原文、四部分分析结果和关联关系一起移入回收站，期间允许恢复。关联问题卡标记为来源已进入回收站，并暂时禁止继续打开来源。回收站内容在删除满 30 天后自动永久清除。
- **Rationale**: 给误删留下恢复窗口，同时设定明确的数据清理期限，避免回收站无限增长。
- **Date**: 2026-09-01

### DECIDED: 资料清除后的问题卡处理
- **Decision**: 仅依赖一份资料的问题卡，在该资料永久清除时一并永久清除。依赖多份资料的问题卡继续保留，但移除已删除资料对应的证据，并标记“部分来源已删除”；剩余来源仍可查看。若其全部来源最终都被删除，该问题卡随最后一份来源一起清除。
- **Rationale**: 防止保留完全无法核验的答案，同时最大限度保住多来源问答中仍然有效的研究记录。
- **Date**: 2026-09-01

### DECIDED: 不修改 HiAgent 后台的结果校验
- **Decision**: 语证服务端要求 HiAgent 按固定四部分返回，并逐条验证所引用文字确实存在于用户原文。无法匹配的引用不显示，其余通过校验的卡片正常保存；缺失部分显示“暂未得到可靠结果”并提供重新分析。分析失败不删除已保存的文字资料，也不修改学校 HiAgent 后台配置。
- **Rationale**: 在现有学校接口能力范围内提高结构稳定性和引用可信度，同时允许部分有效结果先交付。
- **Date**: 2026-09-01

### DECIDED: 正式粘贴文字长度
- **Decision**: 单份粘贴文字最多 30,000 个字符。较长内容由语证自动分段分析并合并为四部分结论；页面显示字符数和预计分析时间。超过上限时提示用户按章节拆成多份资料；完整课本优先使用正式文件上传。
- **Rationale**: 在覆盖一般论文和章节材料的同时，降低超时、上下文截断和合并失真的风险。
- **Date**: 2026-09-01

### DECIDED: 隐私边界与密钥安全
- **Decision**: 页面明确提示“文字资料将保存到你的私人知识库。开始分析后，内容会发送至学校 HiAgent 服务。”Supabase 通过账号隔离资料；原文、结果和密钥不得写入 Git；浏览器不长期缓存正文；运行日志不记录完整原文；界面不显示提示词等技术语言；API 密钥仅保存在服务端环境变量中，前端不可读取。方案完成后、实施前必须使用 Codex Security 做代码安全扫描，重点检查 API Key 是否进入客户端代码、提交历史、日志、构建产物或公开接口。扫描与报告不得输出真实密钥值。
- **Rationale**: 正式持久化和调用学校服务前，必须让用户理解数据去向，并以技术检查防止关键凭据泄露。
- **Date**: 2026-09-01

### DECIDED: 全站改版范围
- **Decision**: 重新设计全部用户可见页面，包括登录、注册、账号恢复、首页、知识库列表、单个知识库与文档管理、正式粘贴文字、四部分分析、证据问答卡片与全屏详情、回收站，以及通用导航、提示、空状态和错误页面。不修改 Supabase 或学校 HiAgent 后台，不新增管理员后台；现有账号、文档和接口数据必须兼容，不能通过清空数据完成改版。
- **Rationale**: 让产品形成一致且完整的品牌体验，同时严格控制外部系统和数据迁移风险。
- **Date**: 2026-09-01

### DECIDED: 实施顺序与验收门槛
- **Decision**: 依次执行实施前代码安全扫描、Product Design 审查与信息架构、design-md 全站规范、正式粘贴文字和四部分卡片、证据问答及全屏详情、其他用户页面统一改造、商标替换、实施后安全扫描与完整验证。每个阶段单独提交 Git；先交付本地版本，不部署；只有测试通过且用户确认停止修改后，才讨论正式部署。
- **Rationale**: 将高风险的数据与密钥问题前置，减少大范围返工，并为每个功能阶段保留可回退的版本节点。
- **Date**: 2026-09-01
