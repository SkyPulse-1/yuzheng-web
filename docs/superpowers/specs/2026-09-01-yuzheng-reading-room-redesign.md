# 语证“学术阅览室”正式功能与全站改版设计

## 目标与边界

本阶段把临时“粘贴文字分析”升级为正式资料，并将证据问答改造成可保存、可检索的研究卡片工作台。全站采用“现代学术阅览室”视觉系统，在不清空现有数据、不修改 Supabase 控制台配置、不修改学校 HiAgent 后台的前提下完成。

本地版本完成并通过验证后交给用户体验；本阶段不部署。新的商标图片由用户后续提供，不阻塞其他功能。此前安全扫描记录的配额、并发限制与恢复码锁定风险暂不修复，但不得扩大密钥暴露面。

## 已选设计方向

采用方案 1“学术阅览室”。桌面端充分使用横向空间，以约 280–320px 的左侧资料架和弹性的右侧研究工作区构成主布局。暖象牙色纸张、深墨文字、深靛蓝交互色和暖金证据色形成统一主题；标题使用宋体风格，正文和控件使用中性无衬线体。

动效服务于状态确认：选中资料轻微抬升并显现靛蓝轮廓；问题卡进入时使用短距离位移和透明度过渡；卡片悬停最多放大 1.02，出现克制跟随光泽；证据上下文展开使用柔和淡入与距离衰减。所有动效尊重 `prefers-reduced-motion`，减少动效时只保留必要状态变化。

## 正式文字资料

用户在知识库中选择“粘贴文字”，填写标题和正文。单份正文最多 30,000 个字符，页面实时显示字符数和预计处理时间。保存前允许修改；保存后仍可检查，开始分析后标题和正文立即锁定。需要修改时必须删除原资料并新建，避免旧结论与新原文错配。

文字资料遵循“先保存、后分析”：

1. 保存标题和正文到当前账号、当前知识库。
2. 保存成功后显示“开始分析”。
3. 用户启动分析后，服务端将内容按需要分段发送到学校 HiAgent，再合并固定结果。
4. 原文和分析结果持久保存，同一账号跨设备可见。
5. 失败不删除资料；已通过校验的部分正常保存，失败部分可重试。

页面显示隐私提示：“文字资料将保存到你的私人知识库。开始分析后，内容会发送至学校 HiAgent 服务。”浏览器不长期缓存完整正文，服务端日志不记录完整原文。

## 四部分分析结果

每份已分析资料固定显示四张卡：

1. 内容摘要
2. 关键观点
3. 原文依据
4. 信息不足与歧义

前三部分中的每条结论必须绑定至少一段能在原文中精确匹配的来源文字。无法匹配的普通结论不保存、不展示；第四部分可在没有直接引文时显示，但必须标记为“综合判断”。某部分没有可靠结果时显示“暂未得到可靠结果”，不得补写或编造。

卡片默认显示摘要预览，悬停时轻微放大并强化轮廓，点击或按回车后全屏展开。全屏详情中，用户悬停在总结内容上时显示对应原文上下文；核心证据句最清晰，距离越远的上下文越淡。触屏设备改为点击打开或关闭上下文。

## 证据问答工作台

证据问答采用左右布局：

- 左侧资料架同时列出上传文件和粘贴资料的标题、类型与处理状态，支持搜索以及选择一个或多个资料。
- 未选择资料时，默认范围为当前知识库内全部可分析资料；有选择时，仅使用选中的资料。
- 右侧上方是问题卡片列表，按最新提问优先排列；首次加载 12 张并支持继续加载和按问题文字搜索。
- 右侧底部固定输入栏，用户可自由输入“核对、比较、梳理”等分析需求，并始终能看到当前选中资料数量。

提交后立即创建“分析中”卡片，防止大块空白和重复提交。完成卡片展示问题、回答摘要、证据数量、来源数量和时间。点击卡片或按回车进入全屏详情，集中展示完整回答、证据卡和来源上下文。删除问题卡前必须二次确认。

问题卡永久保存并跨设备同步。只依赖一份资料的问题卡，在该资料永久清除后一起清除；依赖多份资料的问题卡保留剩余证据并标记“部分来源已删除”，全部来源都被清除时再删除问题卡。

## 删除与回收站

删除资料先进入回收站 30 天，原文、四部分结果和关联关系一起保留并允许恢复。回收站期间，相关问题卡标记来源已进入回收站，暂时不能打开该来源。满 30 天后自动永久清除并按上述来源规则处理问题卡。

## 页面与组件范围

改版覆盖登录、注册、账号恢复、首页、工作台、知识库列表、知识库详情、文件与文字资料、四部分卡片、证据问答、全屏详情、回收站、导航、空状态、加载状态和错误提示。首页与知识库保持不同信息结构，但共享 `DESIGN.md` 规定的颜色、字体、间距、形状和动效语言。

组件边界如下：

- `SourceShelf`：资料搜索、状态展示和单选/多选，不负责问答请求。
- `QuestionBoard`：分页、搜索、处理中与完成卡片，不直接读取原文。
- `QuestionComposer`：收集自定义需求和当前资料范围，阻止重复提交。
- `AnalysisResultCards`：四部分结果预览、缺失状态和全屏入口。
- `SourceContextPopover`：展示匹配原文及距离衰减，不负责匹配算法。
- 服务端资料服务：保存、锁定、软删除、恢复和永久清理。
- 服务端分析服务：分段、HiAgent 调用、固定结构解析和逐条原文校验。

## 数据与服务流程

资料、分析结果、问题卡和来源关联都归属于当前账号并受知识库归属校验。浏览器只调用 Next.js 受控接口；HiAgent 密钥和 Supabase 服务端密钥只存在于服务端环境变量。

文字分析流程为：保存资料 → 用户启动分析 → 锁定资料 → 分段调用 HiAgent → 合并固定四部分 → 校验引用 → 持久化有效结果 → 页面刷新卡片。

问答流程为：选择资料范围 → 输入分析需求 → 创建处理中问题卡 → 服务端调用 HiAgent → 校验证据来源 → 保存回答与关联 → 卡片更新为完成或可重试失败状态。

## 错误与空状态

- 没有资料：提示先上传文件或新建文字资料，并提供单一主操作。
- 有资料但不可分析：清楚说明处理状态，不显示可用的发送按钮。
- HiAgent 超时：保留资料与输入，问题卡显示“未完成”，提供重试。
- 四部分中个别失败：保留可靠部分，失败部分显示“暂未得到可靠结果”。
- 引用无法精确匹配：不展示该引用，不用相似内容冒充。
- 来源进入回收站：问题卡仍可看回答，但来源入口禁用并说明原因。
- 来源部分永久删除：保留仍可核验内容并显示“部分来源已删除”。

错误文案使用日常中文，不出现“Prompt”“系统指令”等技术语言。

## 验收与测试

自动测试至少覆盖：

- 文字资料 30,000 字边界、保存、分析前可修改、分析后锁定。
- 长文本分段与四部分合并。
- 引用精确匹配、无效引用剔除、部分成功和重试。
- 上传文件与粘贴资料混合多选、默认整个知识库范围。
- 问题卡立即创建、完成更新、分页 12 张、搜索、删除确认和跨设备持久化所需接口。
- 资料软删除、恢复、30 天清理，以及单来源与多来源问题卡处理。
- 键盘操作、焦点可见、移动端上下文点击和减少动效。
- 现有注册登录、Library CRUD、文档上传、HiAgent 调用与证据展示不回归。

每个阶段运行相关测试、完整测试、ESLint 和生产构建；最终使用本地浏览器验证主要流程和桌面/移动布局。实施按设计规范、正式文字资料、四部分卡片、问答工作台、回收站、其余页面统一、最终验证的顺序分阶段提交 Git。
