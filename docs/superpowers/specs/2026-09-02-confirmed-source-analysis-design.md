# 资料确认与单份四卡分析设计

## 目标

证据问答页把“勾选资料”和“开始分析”分成两个清晰动作。用户在左侧资料架勾选后，需要点击固定在左侧底部的“确认资料”按钮；确认一份资料时，右侧自动生成四张结构固定、可回到原文的证据结论卡；确认两份或以上资料时，右侧进入自定义分析需求流程。

## 交互状态

### 尚未确认

- 资料复选框只修改待确认范围，不触发网络请求或模型分析。
- 左侧底部显示“确认资料”按钮和当前待确认数量；未选择资料时按钮禁用。
- 右侧显示“选择资料并确认”，不默认分析整个知识库。

### 确认一份资料

- 点击“确认资料”后立即进入单份分析状态，不需要用户再输入问题。
- 若该资料已有可靠的缓存分析结果，直接显示；否则启动一次结构化分析并显示克制的处理中状态。
- 右侧固定显示四张卡：内容摘要、关键观点、原文依据、信息不足与歧义。即使某一部分没有可靠结果，也保留卡片并明确显示空结果。
- 点击任一卡片打开全屏详情。鼠标悬停或键盘聚焦某条总结时，右侧显示它所依据的原文上下文；核心证据最清晰，距离更远的上下文逐渐淡化。触屏设备可点击总结或原文标记。

### 确认两份或以上资料

- 不自动调用模型，避免在用户尚未说明比较目的时产生宽泛结论。
- 右侧显示“从一个分析需求开始”、已有研究记录和底部输入栏。
- 输入栏明确显示只分析已确认的资料；提交后沿用现有问题卡片与全屏详情流程。

## 数据与可靠性

- 单份粘贴文字使用数据库保存的完整原文，四部分结论中的引用必须逐字存在于原文，无法匹配的结论不显示。
- 单份上传文件使用 HiAgent 返回的证据片段作为可信语料，只有引用能够逐字匹配证据片段时才保留。学校文档接口尚未提供完整页文时，上下文范围以返回的证据片段为上限，不伪造更长上下文。
- 分析结果存入现有 `documents.analysis_result_json`，再次选择同一资料时优先复用，避免重复调用。
- 资料处于回收站、无权访问、处理中或接口未配置时，不启动分析并显示人性化错误。
- 客户端只接收分析结果和资料内容，不接收、保存或显示 HiAgent API 密钥。

## 组件边界

- `SourceShelf` 管理待确认的资料复选框、清除和确认按钮，只通过回调提交确认范围。
- `AssistantWorkspace` 管理已确认范围、单份或多份模式、请求状态和结果缓存。
- `SingleSourceAnalysisPanel` 只负责单份资料的处理中、错误和四卡结果状态。
- `AnalysisResultCards`、`AnalysisDetailDialog` 和 `SourceContextPopover` 继续负责四卡、全屏详情和悬停上下文，不重复实现。
- 单份结构化分析由独立服务和 API 路由负责；多份资料继续使用现有 `/api/chat`。

## 验证

- 单元测试覆盖：勾选不自动分析、确认一份触发一次分析、确认多份不自动分析、四卡始终存在、全屏详情及悬停上下文、缓存结果复用、来源引用过滤。
- 浏览器验证当前两份粘贴文字资料的单选和多选流程，检查桌面与窄屏布局、键盘焦点、加载状态和错误状态。
