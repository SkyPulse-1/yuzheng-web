# 单资料追问卡片与 A/B 动效设计

## 目标

单份资料确认后，四张固定证据卡继续作为基础分析结果，同时保留自定义分析输入栏。用户提交新的分析需求时，系统立即创建一张新的研究卡片，插入“内容摘要”之后；原有卡片依次向后移动。页面提供原生 FLIP 与 Motion 两种动效模式，方便在相同数据和布局下直接比较，最终再决定保留哪一种。

## 卡片排列

右侧使用同一个证据卡片网格，顺序固定为：

1. 内容摘要。
2. 当前资料的自定义研究卡片，按创建时间倒序排列，最新一张始终紧跟内容摘要。
3. 关键观点。
4. 原文依据。
5. 信息不足与歧义。

提交新需求后，先插入一张 `PROCESSING` 状态的乐观卡片，已有自定义卡片和后三张固定卡片向后移动。接口完成后只更新原卡片内容和状态，不再次改变位置。失败时保留卡片，并在卡片内显示可理解的错误信息。

只显示分析范围恰好为当前单份资料的研究卡片，避免其他资料或多资料比较结果混入当前证据台。重新打开页面时，从现有问题记录中过滤并恢复这些卡片。

## 输入栏与数据流

单资料模式继续使用现有分析输入栏，文案明确为“仅分析当前资料”。提交时调用现有 `/api/chat`，请求内只包含已经确认的一个资料 ID。返回的问题卡片继续保存到现有 `conversations` 与 `messages`，因此刷新、多设备登录和再次进入工作台后仍可查看。

输入栏在桌面端固定于右侧工作区底部，卡片网格增加足够底部留白；移动端保持单列并避免遮挡最后一张卡片。分析期间输入栏禁用，防止同一用户重复提交造成顺序混乱。

## A/B 动效模式

### A：原生 FLIP

- 使用浏览器 Web Animations API 记录更新前后的卡片位置并计算位移。
- 新卡片从轻微缩小、透明和柔焦状态进入，约 520 毫秒内落位。
- 后续卡片从旧位置平滑移动到新网格位置，不修改业务数据或 DOM 顺序。
- 点击卡片时使用原生 View Transition；不支持该能力时退化为现有全屏弹层过渡。

### B：Motion

- 新增 `motion` 依赖，使用 `LayoutGroup`、`AnimatePresence` 和 `layout` 完成共享布局动画。
- 卡片插入、位置交换、处理中到完成状态均使用弹性受控、不过度回弹的过渡。
- 点击卡片使用共享 `layoutId` 扩展到全屏详情；关闭时反向收回。

两种模式共享完全相同的卡片组件、数据、状态和视觉参数，只替换动画适配层。标题区域提供简洁的“A 原生 / B Motion”分段切换，切换时不清空结果、不重新请求接口。

## 视觉与交互质感

- 卡片使用现有暖象牙、深靛蓝和证据金色体系，不更换品牌风格。
- 默认卡片依靠细边框、纸张层次和柔和阴影建立空间关系；鼠标经过时最多放大至 1.016。
- 光泽只在卡片内部跟随指针，边缘出现轻微靛蓝高光，不使用大面积彩色渐变。
- 新卡片落位时允许一次短暂的边缘光扫，完成后恢复静态，避免持续干扰阅读。
- 全屏详情的背景、标题、正文和来源上下文分层进入，关闭按钮始终可见；Esc 关闭并恢复触发卡片焦点。
- 触屏设备以点击代替悬停；键盘用户可完整操作卡片、切换器、输入栏和详情。
- `prefers-reduced-motion` 开启时，两种模式都取消位移、缩放、模糊和共享元素动画，仅保留瞬时状态变化。

## 组件边界

- `AssistantWorkspace` 继续管理问题列表、提交、失败和详情状态，并允许单资料模式提交问题。
- `SingleSourceAnalysisPanel` 负责组合固定证据卡、自定义研究卡、A/B 切换和输入栏。
- 新增统一的证据卡片网格组件，将固定分析部分与问题卡片映射为稳定 ID 的排列项。
- 原生动效适配层只负责 FLIP 测量和 View Transition，不读取或修改业务数据。
- Motion 动效适配层只负责 `LayoutGroup`、`AnimatePresence` 和共享布局参数。
- `AnalysisDetailDialog` 与 `QuestionDetailDialog` 继续显示实际内容和来源证据，通过统一的打开状态接收动效模式。

## 错误与降级

- Motion 模块加载失败时自动使用原生模式，页面功能不受影响。
- View Transition 不可用时使用 CSS 全屏弹层动画。
- `/api/chat` 超时或失败时保留失败卡片，用户可以关闭详情后重新提交，不删除原始资料。
- 无可靠证据时明确显示“没有返回可核验的原文证据”，不生成虚假来源。

## 验证

- 组件测试覆盖单资料模式仍显示输入栏、请求只携带一个资料 ID、新卡片插入第二位、后续问题按时间倒序、失败卡片保留。
- 两种动效适配层测试稳定 ID、减少动态效果和切换时状态不丢失。
- 浏览器实测 A/B 两种模式的新卡片插入、连续两次提交、卡片展开与关闭、Esc、键盘焦点、窄屏布局。
- 完整运行测试、Lint、TypeScript 和生产构建。
