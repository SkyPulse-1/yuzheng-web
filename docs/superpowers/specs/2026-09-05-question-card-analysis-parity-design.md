# 自定义提问卡片与四类分析卡片统一设计

## 目标

用户每次提交自定义分析需求后生成一张研究卡片。该卡片与“内容摘要、关键观点、原文依据、信息不足与歧义”四类固定卡片采用同一视觉语言、信息层级、交互方式和客观表达风格，同时保留用户问题作为标题。

## 范围

- 统一卡片外框、字号、间距、数量标签、悬停玻璃光效、打开入口和进出场动画。
- 统一详情页的全屏结构、关闭动画和证据查看方式。
- 将自定义问答结果规范为“分析结论、原文依据、信息不足”三类信息，保持一问一卡，不拆成四张卡片。
- 没有可靠依据时明确显示“资料中未提供足够依据”，不得补写资料中不存在的事实。
- 保留现有 Conversation、Message、Evidence Card 数据结构和 HiAgent 运行时协议。

## 组件设计

### 卡片列表

自定义提问卡片复用固定分析卡片的视觉骨架：左上角使用“研究结论”眉题，主体标题显示用户原始问题，摘要区展示简洁结论，右上角显示证据数量，底部统一使用“打开详情”。删除操作继续保留，但作为次级操作，不改变主卡片点击区域。

### 全屏详情

详情弹窗复用固定分析详情的容器、标题栏、滚动行为和过渡动画。内容按以下顺序呈现：

1. 分析结论：回答用户问题的核心判断。
2. 原文依据：逐条显示主张、原文片段、资料名和页码；存在本地文档映射时可打开原文。
3. 信息不足：当证据为空或答案明确表示无法判断时显示可靠性提示。

### 语言规则

- 使用陈述句和证据导向表达，不使用聊天式寒暄。
- 结论先行，避免重复用户问题。
- 每项判断尽量与原文证据对应。
- 证据不足时明确说明边界，不猜测、不补写。

## 数据流

现有 `/api/chat` 继续保存 HiAgent 的 `answer` 和 `evidence_cards_json`。前端增加一个纯转换层，将 Question 数据映射为统一的卡片展示模型，不修改数据库表、不修改 HiAgent Provider、不改变对话协议。

## 异常状态

- `PROCESSING`：使用同款卡片骨架显示“正在核对所选资料”，不可打开空详情。
- `FAILED`：保持同款骨架，显示失败原因与重试提示，不伪造结论。
- 无证据：允许显示回答，但在详情中明确标为“资料中未提供足够依据”。

## 测试

- 验证自定义卡片拥有与固定卡片一致的视觉类名和信息层级。
- 验证完成、处理中、失败、无证据四种状态。
- 验证点击打开统一全屏详情、关闭动画和原文链接。
- 运行 `npm test`、`npm run lint`、`npm run build`。

## 非目标

- 不拆分为四张新卡片。
- 不修改 Supabase schema、文档状态机或 HiAgent 后台。
- 不合并 PR，不部署生产环境。
