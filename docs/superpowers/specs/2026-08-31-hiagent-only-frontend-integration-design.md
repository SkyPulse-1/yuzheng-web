# HiAgent 只读外部平台与前端接入设计

## 目标

在不修改学校 HiAgent 配置、不复制或保存用户密钥的前提下，完善 `yuzheng-web` 的文件保存、处理状态和 HiAgent 调用边界。上传限制直接采用学校 HiAgent 的实际处理范围：PDF 100MB、DOCX 50MB、TXT 30MB，避免出现“上传成功但无法分析”的超限文件。

## 已确认的外部条件

- 已发布的“语证｜可溯源学术证据助手”是对话型智能体。
- 发布页提供 API Base URL、API Key、Web 服务、WebSDK 和 A2A 服务。
- 对话调用流程为 `create_conversation` 后调用 `chat_query_v2`。
- 已绑定两个工作流工具：`语证-Agent-火山杯` 和 `知识库写入`。
- 智能体开启了知识库强制模式，但当前提示词出现未定义变量提示，且提示词中的工作流称呼与绑定工具名称不完全一致。
- HiAgent 的知识库上传需要学校管理员额外开放 `up-upload` 服务；前端项目目前没有该服务地址。
- HiAgent 文档处理限制为：PDF 100MB、DOC/DOCX 50MB、TXT 30MB、图片 10MB、XLS/XLSX/CSV 20MB。论文 PDF 另有最多 200 页限制。
- 学校 HiAgent 自带知识库接口，因此火山引擎账号不是 V1 的必需条件。

## 不可越界事项

- 不修改 HiAgent 的提示词、变量、工作流、知识库、发布状态或访问控制。
- 不点击创建、显示、复制或更新任何 API Key、AK、SK、Token 或其他凭据。
- 不把服务端密钥写入浏览器代码、数据库、日志、测试快照或 Git。
- 不把未经验证的自然语言文档名当作多用户隔离边界。
- 不删除现有 VikingDB 适配器文件；先停止新流程依赖它，保留回退和历史代码。
- 不把“文件已保存”错误显示为“知识库已解析完成”。

## 方案比较

### 方案 A：Supabase 保存 + HiAgent 受控适配（采用）

浏览器将文件直接上传到私有 Supabase Storage，Next.js 服务端负责鉴权、元数据和状态转换。文件符合 HiAgent 类型和大小限制且学校提供 `up-upload` 地址后，再由服务端调用 HiAgent；否则保留为“已保存，暂不可分析”。问答通过服务端 HiAgent 适配器完成，密钥始终只在服务端。

优点是上传限制与实际分析能力一致、避免 Vercel 请求体限制、不会要求用户再注册火山引擎，并且可以独立交付当前可用部分。缺点是学校未提供上传服务地址前，文档入库和真实证据检索无法完成。

### 方案 B：直接调用 HiAgent 知识库 OpenAPI（不采用）

服务端直接使用学校 HiAgent 的 AK/SK、网关地址、WorkspaceID 和 DatasetID 创建及管理知识库文档。该方案能力完整，但需要新建和保存高权限长期凭据，还要求学校提供上传网关与签名参数，不符合当前“不要动 HiAgent、不要复制密钥”的约束。

### 方案 C：继续强制依赖火山知识库（不采用）

保留现有 VikingDB 作为唯一文档入库和检索后端。该方案与学校 HiAgent 的已有知识库和工作流重复，需要额外账号、AK/SK、知识库资源和过滤标签，不符合“没有必要就不要火山知识库”的要求。

## 系统边界

### 浏览器端

- 负责选择文件、显示真实上传进度、暂停后重试和状态说明。
- 单文件限制为 PDF 100MB、DOCX 50MB、TXT 30MB。
- 使用 Supabase Storage 的可恢复上传能力，文件内容不经过普通 Next.js 表单请求。
- 浏览器只获得当前用户、当前文件的一次性上传授权，不获得 Supabase service role 或 HiAgent 密钥。

### Next.js 服务端

- 验证当前 Supabase 用户和 Library 所有权。
- 为上传签发当前用户目录下的一次性授权，并在上传完成后创建或完成文档记录。
- 根据扩展名、MIME 和文件大小判断“可保存”和“可交给 HiAgent 处理”是否成立。
- 保存 HiAgent 会话标识并代理 `create_conversation`、`chat_query_v2` 请求。
- 在学校上传服务地址和隔离规则未验证前，不声称文件已进入知识库。

### Supabase

- Auth 负责用户身份；用户名唯一性继续由现有数据库约束保证。
- PostgreSQL 保存 Library、Document、Conversation、Message 和 Evidence Card 元数据。
- 私有 Storage 保存原始文件，路径继续包含 `owner_id/library_id/document_id`。
- RLS 是第一层租户隔离；服务端查询仍显式校验 owner 与 library 关系。

### 学校 HiAgent

- 作为外部只读依赖使用，项目不会通过自动化修改其配置。
- 对话接口只有在服务端配置完整时启用。
- 文档入库只有在管理员提供 `up-upload` 地址并确认用户隔离字段后启用。
- `UserID` 使用 Supabase 用户 UUID，保证同一应用内唯一且多设备一致。

## 文件状态

文档状态扩展为以下语义：

- `UPLOADING`：正在上传到 Supabase。
- `STORED`：文件已安全保存，但当前不能提交给 HiAgent，例如学校上传服务未提供。
- `PROCESSING`：已提交给知识库后端，正在解析或索引。
- `READY`：后端明确返回处理完成，可参与问答。
- `FAILED`：上传或处理明确失败，并提供可重试原因。
- `DELETING`：正在删除关联内容。

不得把没有 `kb_document_id` 或没有后端成功状态的文档自动标记为 `READY`。

## 上传与处理规则

1. 浏览器先校验文件扩展名、MIME、非空和类型对应上限：PDF 100MB、DOCX 50MB、TXT 30MB。
2. 服务端再次执行相同校验，并签发一次性私有上传授权。
3. 浏览器通过可恢复上传将文件直接写入 Supabase Storage。
4. 浏览器通知服务端完成上传；服务端核对对象路径、大小和当前用户后完成文档记录。
5. 超出类型上限的文件在上传前阻止，并显示对应的准确限制。
6. 未配置学校 `up-upload` 服务时，文件保存后转为 `STORED`，显示“文件已保存，学校文档处理服务尚未接通”。
7. 只有实际提交成功后转为 `PROCESSING`；只有轮询确认成功后转为 `READY`。

## HiAgent 对话适配

现有适配器默认调用工作流端点，与当前已发布的对话型智能体不一致。新适配器采用：

1. 新会话调用 `POST create_conversation`，Header 使用服务端 `Apikey`，Body 包含唯一 `UserID`。
2. 保存返回的 `AppConversationID`，后续同一 Supabase Conversation 复用。
3. 问答调用 `POST chat_query_v2`，Body 包含 `UserID`、`AppConversationID`、`Query`。
4. 服务端解析 SSE 事件，只向前端返回整理后的回答和证据数据，不回传密钥或原始内部错误。
5. GENERAL、SINGLE、MULTI 的范围仍由当前 Library 和已验证 Document 记录生成，浏览器不能传入 `owner_id`。
6. 在 HiAgent 未确认按 `owner_id + library_id` 强制过滤之前，保持可信过滤开关关闭；界面明确显示服务尚未完成安全接入。

## 用户界面

- 上传按钮保留简洁外观，新增百分比进度和明确阶段文本。
- 文档列表区分“已保存”“处理中”“可分析”“处理失败”。
- 超限说明使用普通产品语言，不出现提示词、模型内部指令或开发者术语。
- 问答不可用时说明缺少的是“学校文档处理服务”，不让用户误以为文件丢失。
- 已上传文件仍可下载和删除；删除继续要求当前用户拥有该文档。

## 错误处理

- 上传中断：保留文档或上传会话信息，允许用户重试，不创建重复对象。
- 文件超限：上传前阻止并显示该文件类型的准确上限，不创建空文档记录。
- HiAgent 超时：保留用户消息和 Supabase 文件，返回可重试提示。
- HiAgent 返回无效事件或缺失答案：记录非敏感错误分类，不记录 Header、请求密钥或完整响应。
- 学校服务 502/维护：不修改外部配置，前端显示暂时不可用。
- 删除知识库关联失败：不先删除 Supabase 原文件，避免产生无法恢复的孤立状态。

## 测试与验收

- 单元测试覆盖 PDF 100MB、DOCX 50MB、TXT 30MB 的准确边界。
- API 测试覆盖未登录、跨用户 Library、伪造 Storage 路径和重复完成上传。
- HiAgent 适配器测试覆盖创建会话、复用会话、SSE 文本聚合、超时和敏感字段不出现在返回值。
- 文档状态测试覆盖 `UPLOADING → STORED`、`UPLOADING → PROCESSING → READY` 和失败重试。
- UI 测试覆盖上传进度、超限提示、学校服务未接通提示和问答禁用状态。
- 继续运行 lint、build 和现有全部测试，避免破坏登录、Library CRUD、文档管理和首页证据轮播。

## 当前可交付结果

本轮可以完成：按类型限制的直传流程、真实状态展示、对话型 HiAgent 适配器结构、服务端安全边界和自动化测试。学校未提供 `up-upload` 地址、知识库标识和租户过滤确认前，文档真实入库与按用户隔离的证据检索只能保持安全关闭；这属于外部依赖，不通过伪造成功状态绕过。
