# 语证 Web App V1.0 界面统一设计

## 目标

让第一次使用语证的用户无需教程，就能依次完成注册或登录、创建知识库、上传文档、等待处理和进入问答。界面应简洁、专业、具有学术产品辨识度，并在电脑与手机上保持清晰可用。

## 视觉方向

采用“暖色学术极简”风格。主背景为米白和浅石色，正文使用墨黑和深灰，琥珀色只用于品牌强调与关键提示。保留衬线标题与无衬线正文的组合，减少无功能装饰，不使用影响阅读的复杂动画。

## 页面结构

### 首页

首页只承担产品说明和开始使用两个任务。首屏突出“在自己的资料里，找到有出处的答案”，主要按钮进入登录或用户工作区，次要内容说明限定检索范围、证据优先和返回原文三项原则。

### 登录与注册

默认显示邮箱密码登录。注册为清晰的第二入口，邮件链接放入“其他登录方式”。登录、注册和邮件链接共用同一页面框架，并提供明确的成功、错误和等待提示。密码输入支持显示或隐藏，表单使用浏览器自动填充语义。

### Dashboard

首页展示当前账号、最近知识库和唯一主要操作“新建知识库”。知识库卡片展示名称、描述、真实文档数量和更新时间，不显示无依据的固定数字。

### 知识库与文档

知识库列表突出创建、打开和管理。详情页按“知识库信息、上传区域、文档列表、进入助手”组织。文档状态统一为等待处理、处理中、可使用、处理失败，并为失败状态提供重试入口。

### 助手工作区

桌面端保持三栏：文档选择、问答、证据卡。移动端按“选择材料、问答、证据”顺序折叠。主要操作始终是发送问题；证据卡显示来源文档、页码、证据类型和查看原文入口，不展示用户难以理解的内部检索分数。

## 组件规范

- 全站共用顶部导航、页面标题、主要按钮、次要按钮、输入框、提示框、空状态和状态标签。
- 每个页面只设置一个视觉最强的主要操作。
- 所有可点击元素具备悬停、键盘焦点和禁用状态。
- 页面最大宽度、左右留白、卡片圆角和阴影保持一致。
- 成功使用绿色，警告使用琥珀色，失败使用红色，处理中使用蓝灰色；颜色之外同时提供文字状态。

## 用户流程与数据流

1. 用户注册或登录，Supabase 创建或恢复会话。
2. Dashboard 读取当前用户拥有的知识库及其文档数量。
3. 用户创建知识库并上传材料，页面展示真实处理状态。
4. READY 文档可以进入助手选择范围。
5. HiAgent 返回回答与证据卡，证据卡链接到受权限保护的原文页码。

所有现有 RLS、登录保护和服务端密钥边界保持不变。界面改造不改变数据库表结构，也不删除现有用户、知识库或文档。

## 错误与空状态

错误信息使用普通中文说明发生了什么以及下一步怎么做。空知识库提示创建知识库；空文档列表提示上传材料；无 READY 文档时禁止开始真实问答并解释原因。网络或服务错误不伪装为成功状态。

## 响应式与无障碍

以手机单列布局为基础，桌面端扩展为多栏。正文保持可读字号和行距，表单标签始终可见，颜色对比满足基础可读性要求，键盘操作能覆盖表单和主要导航。

## 验收标准

- 新用户能从首页进入注册，并清楚区分登录、注册和备用邮件链接。
- 登录用户能在三次主要点击内创建知识库并看到上传入口。
- 所有页面的主要按钮、输入框、提示与状态样式一致。
- 文档数量和状态来自真实数据，不出现硬编码演示值。
- 证据卡可打开对应文档页码。
- 375px 手机宽度和常见桌面宽度无横向溢出或遮挡。
- `npm run lint` 与 `npm run build` 通过。

## 不在本轮范围

本轮不新增社交登录、不修改 Supabase 数据结构、不接入新的第三方服务、不重做 HiAgent 或 VikingDB 业务逻辑，也不进行 Vercel 部署。
