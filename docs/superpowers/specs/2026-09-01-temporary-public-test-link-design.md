# 语证临时公网测试链接设计

## 目标

为尚未正式部署的语证 Web App 提供一个临时 HTTPS 地址。测试者只需打开链接即可体验当前版本，无需安装 Node.js、下载源码或配置 Supabase。

## 范围

- 使用当前功能分支的生产构建运行本地 Next.js 服务。
- 优先使用 Cloudflare Quick Tunnel；因当前学校网络阻止其 UDP/TCP `7844` 出站连接，经用户确认后改用通过 SSH `443` 端口工作的 Pinggy 临时 HTTPS 隧道。
- 测试者使用各自新注册的用户名和密码进行测试。
- 测试结束后停止本地服务和隧道，公网地址随即失效。
- 正式部署、固定域名和 HiAgent 文档处理接入不属于本次范围。

## 安全约束

- 不复制、导出、提交或展示 `.env.local` 及其中任何值。
- 不把 Supabase Secret Key、HiAgent API Key、签名密钥或恢复码密钥写入源码、压缩包、日志或公网地址。
- 只暴露 Next.js 生产服务端口，不暴露数据库端口、开发调试端口或本机其他服务。
- 所有 Library、文档和证据访问继续要求登录，并沿用现有用户所有权校验与 Supabase 行级安全策略。
- 测试链接只发给指定测试者；测试期间保持电脑开机，结束后停止隧道。
- 不使用真实敏感资料进行公开测试；测试者只上传允许用于测试的文件。

## 运行结构

1. 对当前功能分支执行测试、代码检查和生产构建。
2. 在独立端口启动 `next start`，仅作为本次测试源站。
3. 使用 Windows 自带 OpenSSH 连接 Pinggy `443` 端口，将随机 HTTPS 地址转发至该端口。
4. 从公网地址检查首页、注册、登录、Library CRUD、文档上传界面、下载和删除入口。
5. 把临时链接及当前已知限制交给用户。

## 数据流

浏览器请求先到 Pinggy 临时域名，再由 SSH 反向隧道转发至本机 Next.js 生产服务。Next.js 按现有服务端配置访问 Supabase。服务端密钥不发送给测试者，也不进入浏览器页面。

## 错误处理

- 如果生产构建失败，不启动公网隧道，先报告本地错误。
- 如果隧道连接失败，保留本地版本，并报告网络或学校网络限制。
- 如果公网地址无法注册或登录，停止对外分享并检查回调地址、Cookie 和 Supabase 配置。
- 如果发现接口未验证登录或所有权，停止隧道，不向测试者发送链接。

## 验收标准

- 公网 HTTPS 地址可以打开语证首页。
- 未登录用户不能读取 Library、文档或证据数据。
- 两个不同测试账号的数据互不可见。
- 测试者无需安装软件或获得任何项目密钥。
- 关闭隧道后，临时公网地址不可继续访问。
- 页面明确保留当前限制：HiAgent 文档处理尚未完成，上传文件只完成安全保存时不得显示为已完成知识库解析。
