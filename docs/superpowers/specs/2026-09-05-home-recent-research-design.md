# 首页最近研究展示修复设计

## 目标

让首页稳定呈现用户最近完成的真实研究记录，同时保持来源可信。背景书页仅承担视觉装饰，不展示可能被误认为真实研究内容的具体文字。

## 展示规则

- 登录用户最多展示三个最近完成的工作台，仍按 20 秒轮换，悬停或键盘聚焦时暂停。
- 每项显示真实知识库名称、真实问题标题和最新一条助手回答的简短摘要。
- 有可映射到当前知识库文档的证据卡时，显示证据结论、来源文档、页码和“查看原文”。
- 没有可靠证据映射时，显示真实回答摘要，并明确标注“尚未形成可回溯证据”；不显示虚构来源或“查看原文”。
- 工作台名称、问题标题和继续研究入口均跳转到对应证据问答工作台。
- 未登录、没有记录或读取失败时，保留清晰的空状态，不使用示例数据冒充用户记录。

## 数据流

首页服务端读取当前登录用户可见的已完成会话、最近助手消息、知识库和相关文档。`buildRecentResearchWorkspaces` 负责把这些数据整理成首页视图模型，并对回答摘要做去空白与长度限制。证据来源只有在 `document_id` 能映射到同一知识库中未删除的本地文档时才被信任。

## 视觉处理

- 保留现有纸张、阴影和轻微玻璃质感。
- 替换背景书页中的具体标题和正文为低对比度的抽象行纹、索引点和页码符号。
- 最近研究卡保持前景最高对比度，真实问题与回答摘要成为视觉重点。
- 不新增强烈动效；继续遵守 `prefers-reduced-motion`。

## 错误与安全边界

- Supabase 查询失败时显示“最近研究暂时无法读取”，不暴露错误详情。
- 不放宽 RLS、资源归属校验或证据来源校验。
- 不把无 `document_id` 的 HiAgent 内容伪装成可回溯原文。
- 不更改 HiAgent、文档状态机、上传流程和数据库结构。

## 验证

- 单元测试覆盖：有可靠证据、有真实回答但无可靠证据、无记录三种情况。
- 运行 `npm test`、`npm run lint` 和 `npm run build`。
- 浏览器检查首页真实记录、链接、空状态、20 秒轮换和响应式布局。
